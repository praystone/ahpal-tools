📚 什麼是 JSON？給門外漢的完整說明

你可能看過這種東西：{"name": "小明", "age": 25}。這就是 JSON。它不是程式語言，是「資料的格式」。

但它為什麼叫 JSON？為什麼全世界的 API 都用它？為什麼它有時候會「格式錯誤」？這篇文章一次講清楚。

一、JSON 是什麼？一句話講完

JSON = JavaScript Object Notation（JavaScript 物件表示法），是一種「用文字描述資料」的格式。

它的規則很簡單：用 {} 包「物件」、用 [] 包「陣列」、用 "key": "value" 表示「鍵值對」。

JSON 不是程式語言，它只是「文字」。任何程式語言（Python、JavaScript、PHP、Java）都能讀寫 JSON。這就是它為什麼成為「跨語言的資料交換標準」。

二、為什麼叫 JSON？由來是什麼？

JSON 是 2001 年由 Douglas Crockford 提出的。他發現 JavaScript 的「物件語法」很適合描述資料，於是把它抽出來，變成一種「獨立的資料格式」。

JSON 的語法幾乎跟 JavaScript 的物件一樣，但它不是 JavaScript，它是「所有程式語言都能用的資料格式」。這就是為什麼它叫「JavaScript Object Notation」——「源自 JavaScript 的物件表示法」。

2006 年，JSON 被正式標準化（RFC 4627），從此成為網際網路的「資料交換標準」。

三、JSON 的 6 種資料型別

型別範例說明
字串（string）"小明"用雙引號包
數字（number）25、3.14整數或小數
布林（boolean）true、false只能是「小寫」
空值（null）null表示「沒有值」
陣列（array）[1, 2, 3]用 [] 包
物件（object）{"name": "小明"}用 {} 包

四、JSON 的 3 個常見錯誤

錯誤 1：用單引號

JSON 只認「雙引號」。{'name': '小明'} 是錯的，要寫 {"name": "小明"}。

錯誤 2：布林值大寫

JSON 只認小寫 true、false。大寫 True、False 是錯的（這是 PowerShell 常犯的錯）。

錯誤 3：最後一個元素有逗號

{"a": 1, "b": 2,} 是錯的，最後一個元素不能有逗號。

五、JSON 的實際用途

  • API：幾乎所有 API 都用 JSON 傳資料（GitHub API、天氣 API、AI API）
  • 設定檔：VS Code、npm、Cloudflare 的設定檔都是 JSON
  • 資料庫：MongoDB、Firebase 用 JSON 存資料
  • 前端與後端：前端用 JSON 傳資料給後端，後端用 JSON 回傳
  • 日誌：結構化日誌用 JSON 記錄事件

六、JSON vs XML：為什麼 JSON 贏了？

項目JSONXML
大小小（省頻寬）大（標籤多）
可讀性高低
解析速度快慢
瀏覽器支援原生支援要額外解析

JSON 比 XML 小、快、好讀，所以 2010 年後，幾乎所有 API 都改用 JSON。

七、常見誤解

  • ❌ 誤解：JSON 是程式語言。
    ✅ 事實：JSON 只是「資料格式」，不是程式語言。
  • ❌ 誤解：JSON 只能用在 JavaScript。
    ✅ 事實：JSON 是所有程式語言都能用的資料格式。
  • ❌ 誤解：JSON 可以寫註解。
    ✅ 事實：JSON 不支援註解（這是它最大的缺點）。
  • ❌ 誤解：JSON 的順序不重要。
    ✅ 事實：JSON 的「鍵」順序不重要，但「陣列」順序很重要。
  • ❌ 誤解：JSON 只能存簡單資料。
    ✅ 事實：JSON 可以嵌套（物件裡有陣列，陣列裡有物件），能存複雜資料。

八、這個工具能幫你做什麼？

  • 格式化：把「擠成一團」的 JSON 變成「一行一行」好讀的格式
  • 驗證：檢查 JSON 有沒有語法錯誤（少逗號、多逗號、引號錯）
